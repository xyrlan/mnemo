- **`mnemo land` finds a Rust struct field or a TypeScript type member that a
  contract exposes.** A dotted signature such as `ChildSession.notice:
  Option<String>` is looked up among its owner's members, and only a Python
  class could be read for them (#305). For a Rust `struct` or a TS `type`
  the check fell back to the bare name after a declaration keyword, and a
  field — `notice: Option<String>`, nothing before it — never matched: on
  2026-10-14 that refused mnemo-desktop's `notice` piece over a field it had
  delivered. The owner may now be a Rust `struct`, `enum` or `trait` with
  its `impl` blocks, or a TS `interface`, object `type`, `class` or `enum`.
  As for Python, the lookup stays on that owner: the same name on another
  type, a local, or a field in a struct expression does not count, and a
  free function no longer passes for a member of the type it is qualified
  with. TypeScript's optional marker is accepted in the signature
  (`ChildSession.notice?: string`), which printed as unverifiable. A file
  the reader cannot follow falls back to the old lookup. On 4,495 files from
  three TS/Rust codebases, the members it reads for each of their 5,135
  types match what `syn` and the TypeScript compiler parse, and no other
  name in those files reads as a type (`tools/measure_owner_members.py`).
  (#675)
