- **`pr-follow` no longer wakes a child for checks that never ran or that a
  rerun cleared.** A settled PR used to count as red whenever any check
  failed, so a repository whose GitHub Actions billing had lapsed — every job
  "failing" in two seconds with zero steps — woke its children to fix nothing.
  The watcher now reads the failing check runs on the PR's head as
  `tools/measure_dispatch_outcomes.py` does: a job whose annotation says it was
  never started, or a check a rerun on the same commit passed, is not red. The
  parent is told once per head that the checks did not run (billing), so a
  person can act; a real failure, alone or beside never-run ones, wakes the
  child as before. Annotation reads are capped per pass and never repeated for
  a run; any read that fails falls back to waking. (#575)
