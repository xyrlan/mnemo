# Distribution — design

Date: 2026-09-02. Follows the product audit of 2026-09-01 and the four
corrections-layer workstreams (v1.1.0) plus follow-ups (v1.2.0). Every
technical recommendation from that audit has shipped except host adapters
(#127). What has not shipped is anything that lets a person who is not the
maintainer see mnemo work, keep their rules if they leave, or use it outside
Claude Code.

Three pieces, in dependency order:

| # | Piece | Depends on |
|---|-------|-----------|
| 1 | `mnemo export` — managed rules file for the current project | nothing |
| 2 | Host adapters (Cursor, Codex): MCP registration + rules file | export |
| 3 | Demo GIF: the five-minute loop, recorded from a vhs tape | nothing (records Claude Code only) |

Out of scope, deliberately: early-user recruitment (the user chose to skip
it), hooks and transcript readers for Cursor/Codex (learning stays Claude
Code-only this round; #127 keeps the full seam map), any change to the reflex
scoring, and a landing page.

Real-vault facts these designs rest on (2026-09-02, after reclassify):

- `shared/feedback`: 62 pages; `shared/user`: 2; `shared/reference`: 1361.
- Feedback pages per project (from `sources:`): clubinho 24, meunu 17,
  sg-imports 8, xyrlan 4, five others ≤ 2. An export for one project is
  therefore 1–25 rules, well under a CLAUDE.md budget.
- Every live page carries `slug:` (v1.2.0 migration), `type:`, `name:`,
  `description:`, `sources:` (vault-relative `bots/<project>/...` paths), and
  feedback pages carry `evidence.quote`. PII is already redacted at
  extraction (`core/redact.py`).
- Universal = a rule whose `sources:` span ≥ `universalThreshold` (2)
  distinct projects (`rule_activation.projects_for_rule` / `is_universal`).
- The MCP server is `mnemo mcp-server` over stdio; `install.settings._mcp_server_spec()`
  already resolves the right `command`/`args` for pip, npm and frozen builds.
- The UserPromptSubmit hook's `additionalContext` is **not shown** in the
  Claude Code TUI. A viewer cannot see an injection happen; they can only
  see its effect and `mnemo why`.

## 1. `mnemo export`

### Problem

Rules live only in the vault, in mnemo's own page format. A person who
tries mnemo and stops has nothing; a person who wants to hand rules to a
teammate, a CI agent, or another tool has nothing. This is the single
largest trust objection a community raises against a memory tool, and the
audit listed "veto / leave" as the requests Claude Code's own memory
declined. Export is also the injection surface for hosts without a
UserPromptSubmit hook (piece 2).

### Behaviour

```
mnemo export [--host claude|cursor|codex] [--target auto|rules|claude-md|agents-md]
             [--project <name>] [--types feedback,user] [--all-types]
             [--limit N] [--dry-run] [--remove]
```

- **Selection.** Rules whose `type` is in `--types` (default `feedback,user`)
  and whose `projects_for_rule(sources)` contains the current project **or**
  which are universal. The current project is the vault agent name for the
  cwd, the same resolution the hooks use; `--project` overrides it. `_inbox`
  and `_archive` are never exported (`filters.iter_shared_pages(include_inbox=False)`).
- **Order.** Universal first, then by `len(sources)` descending, then slug.
  `--limit` truncates after ordering; default no limit. When the rendered
  block exceeds ~4k tokens (chars/4) the command prints a one-line warning
  naming `--limit`.
- **Rendering.** One markdown block, host-independent:

  ```
  <!-- mnemo:start — generated by `mnemo export` on 2026-09-02; edit the vault, not this block -->
  ## Rules mnemo learned from you (project: app, 7 rules, 2 universal)

  ### Use yarn, never npm  `use-yarn-not-npm`
  Use yarn, never npm, in this repo. …body without the graph section…
  > you said: "never use npm in this repo, always yarn"

  ### …
  <!-- mnemo:end -->
  ```

  The heading is `name:`, the body is the page body with the
  `<!-- mnemo:graph-section -->` tail stripped, and the `> you said:` line is
  `evidence.quote` when present. Universal rules get ` (universal)` after
  the slug. No frontmatter fields other than these are exported.
- **Targets.** `--target auto` picks per host:

  | host | target | path | file semantics |
  |------|--------|------|----------------|
  | claude | `rules` | `<cwd>/.claude/rules/mnemo.md` | whole file is the block (plus nothing) |
  | claude | `claude-md` | `<cwd>/CLAUDE.md` | managed block inserted/replaced between markers; rest of file untouched |
  | cursor | `rules` | `<cwd>/.cursor/rules/mnemo.mdc` | frontmatter `description: Rules mnemo learned from you` + `alwaysApply: true`, then the block |
  | codex | `agents-md` | `<cwd>/AGENTS.md` | managed block, same as `claude-md` |

  One renderer, four thin writers. A managed-block writer replaces the text
  between the markers if both exist, appends the block with a leading blank
  line if neither exists, and refuses (non-zero exit, no write) if exactly
  one marker is present. Writes are atomic (`core.atomic`).
- **`--remove`** deletes the whole-file targets and strips the block from
  managed-block targets. Files without the markers are left alone.
- **Manifest.** `<vault>/.mnemo/export/<project>.json` (the vault already
  owns `.mnemo/` for `learned.jsonl` and migration markers; the cwd is not
  touched beyond the rules file itself, so nothing new needs gitignoring):

  ```json
  {"host": "claude", "target": "rules", "cwd": "/Users/you/github/app",
   "path": ".claude/rules/mnemo.md", "exported_at": "...",
   "rules": {"use-yarn-not-npm": "<sha256 of rendered entry>", ...}}
  ```

  The rules file is meant to be committed; the manifest is not, and lives
  outside the repo.
- **Staleness.** `mnemo status` gains one line when a manifest exists:
  `Export: 7 rules → .claude/rules/mnemo.md (2 changed in vault since, run mnemo export)`.
  Computed by re-rendering the selection and diffing hashes; no LLM, no
  index rebuild.
- **No double injection.** On the Claude host, if a manifest exists for the
  current project with target `rules` or `claude-md` and its `cwd` matches,
  the reflex (UserPromptSubmit) skips slugs listed in it, because Claude Code already
  loaded them. `mnemo why` shows such candidates as `exported` instead of
  `injected`/`silent`, so the arithmetic stays legible. Cursor/Codex have no
  reflex, so nothing to skip.

### What export is not

- Not a sync. Re-running regenerates the block; nothing flows back from the
  file into the vault. Hand edits to the block are overwritten and the
  header says so.
- Not a dump. `reference` pages (1361) are excluded unless `--all-types` is
  passed, and that flag prints the token warning unconditionally.

### Testing

- Unit: selection (project match, universal, inbox/archive skipped, type
  filter, limit + ordering), renderer (graph section stripped, quote line,
  universal marker), each writer (fresh file, replace between markers,
  one-marker refusal, `--remove` on both shapes), manifest round-trip,
  staleness diff, reflex skip via manifest.
- Integration: on a fixture vault with two projects and one universal rule,
  `mnemo export --dry-run` prints the block and writes nothing; `--host cursor`
  produces valid `.mdc` frontmatter.
- Real vault check before merge (reviewer, not fixtures): `mnemo export --dry-run`
  inside `clubinho` yields ~24 rules and the rendered block reads as rules,
  not narrative.

## 2. Host adapters: Cursor and Codex

### Problem

Issue #127 maps five couplings to Claude Code. This round takes only the two
that are cheap and give a Cursor or Codex user something real: the MCP
server (so `list_rules_by_topic` / `read_mnemo_rule` work) and the rules
file (so the rules are in context without the agent having to ask — the
2026-09-01 data shows agents call the MCP tools rarely, 22 times in 216
sessions, so MCP alone is not enough). Hooks and transcripts stay Claude-only
and the docs say so.

### Behaviour

```
mnemo init --host cursor|codex [--project] [--vault-root …]
mnemo uninstall --host cursor|codex [--project]
```

`--host claude` is the default and changes nothing about today's `init`.

For a non-Claude host, `init`:

1. Preflight and scaffold the vault exactly as today (steps 1–2 of the
   existing init).
2. Registers the MCP server in the host's config (below). No hooks, no
   status line, no memory mirror.
3. Runs `mnemo export --host <host>` for the cwd when the vault has any
   exportable rule; otherwise prints what to do:
   `no rules yet — learn in Claude Code (mnemo learn), then mnemo export --host cursor`.
4. Prints the honest boundary once:
   `mnemo learns from Claude Code sessions. In Cursor it serves what it learned: MCP tools + .cursor/rules/mnemo.mdc. Re-run mnemo export after new rules.`

`mnemo status` and `doctor` report the host: which config file carries the
MCP entry, whether the launch command resolves, and the export line from
piece 1. `doctor` fails the MCP check when the entry is missing or its
command does not exist on disk.

### Per host

**Cursor.** MCP config is JSON with the same `mcpServers` shape Claude uses:
`~/.cursor/mcp.json` (global) or `<cwd>/.cursor/mcp.json` (`--project`).
`install.settings` gets a path-parameterised inject/uninject (today's
`inject_mcp_servers(claude_json_path)` already takes the path; the lock,
backup and idempotence are reused as-is). Rules file: `.cursor/rules/mnemo.mdc`
via export. Plain `.md` under `.cursor/rules` is ignored by Cursor, hence the
`.mdc` extension and the mandatory frontmatter (`description`, `alwaysApply: true`).

**Codex.** MCP config is TOML (`~/.codex/config.toml`, `[mcp_servers.mnemo]`
with `command` and `args`). mnemo does not write TOML: the repo supports
Python 3.8, `tomllib` is 3.11+, and adding a writer dependency for one table
is not worth it. Instead `init --host codex` runs
`codex mcp add mnemo -- <command> <args…>` with the argv from
`_mcp_server_spec()`, and `uninstall` runs `codex mcp remove mnemo`. If the
`codex` binary is not on PATH the command prints the exact TOML table to
paste and exits 0 with a warning. `--project` for Codex is accepted only if
the plan-time check confirms Codex reads `<cwd>/.codex/config.toml`;
otherwise the flag errors with `Codex has no project-level MCP config; omit --project`.
Rules file: `AGENTS.md` managed block at the repo root via export.

### Code shape

`src/mnemo/hosts/` with `__init__.py` (registry + `get_host(name)`),
`claude.py`, `cursor.py`, `codex.py`. Each host exposes exactly what this
round needs and nothing more:

```python
class Host(Protocol):
    name: str
    def register_mcp(self, *, project: bool, cwd: Path) -> RegisterResult: ...
    def unregister_mcp(self, *, project: bool, cwd: Path) -> None: ...
    def export_target(self, cwd: Path) -> ExportTarget: ...   # path + writer kind
    def describe(self, *, project: bool, cwd: Path) -> HostStatus: ...  # for status/doctor
```

`claude.py` wraps the existing `inject_mcp_servers` / `uninject_mcp_servers`
and returns today's `.claude/rules/mnemo.md` target. Hook installation is
**not** moved behind the protocol this round; `init` keeps its current flow
for Claude and branches only for the new hosts. Widening the protocol to
hooks and transcripts is #127's second half.

### Testing

- Unit per host with `tmp_home`: register is idempotent and preserves
  unrelated servers; unregister leaves the file valid; Codex shells out to a
  stubbed `codex` (recorded argv) and falls back to the printed snippet when
  absent.
- `_real_vault_guard` (#117) extends its fingerprint to `~/.cursor` and
  `~/.codex` so no test can touch the developer's real host configs.
- Existing Claude tests unchanged and green: the default host path is
  byte-for-byte today's behaviour (acceptance criterion from #127).
- Manual, before merge: on this Mac, `mnemo init --host cursor --project`
  in a scratch repo, open it in Cursor, confirm the mnemo tools are listed
  and the `.mdc` rule shows under Rules; `mnemo init --host codex`, run
  `codex mcp list`, confirm `mnemo` present and the tool callable.

## 3. Demo GIF

### Problem

The README's five-minute loop is prose. Nobody outside the maintainer has
seen it run. The storyboard in `docs/getting-started.md` ("GIF storyboard")
assumes the injected context is visible in frame 3; it is not, so the
storyboard needs a fourth frame.

### Decision

A committed vhs tape driving the **real** `claude` CLI in a throwaway sample
repo, with a fresh vault. Reproducible by anyone with vhs and a Claude login;
nondeterministic in wording, which is the point — it is not staged.

### Files

- `tools/demo/setup.sh` — creates `$DEMO_ROOT` (default
  `/tmp/mnemo-demo`) containing `app/` (a `package.json`, a `yarn.lock`, a
  one-line README) and an empty vault dir, runs
  `mnemo init --project --vault-root $DEMO_ROOT/vault --yes` inside `app/`,
  and asserts the maintainer's global mnemo is **not** active
  (`~/.claude/settings.json` has no mnemo hooks and the plugin is disabled);
  otherwise it exits 1 with the instruction to disable it for the recording.
  Without this assertion the global reflex also fires and frame 4 shows two
  injections.
- `tools/demo/loop.tape` — the recording. Settings: 100 columns × 30 rows,
  font size 16, theme with a light-on-dark palette that survives GIF
  quantisation, `Set PlaybackSpeed 1.0`, output `docs/assets/loop.gif`.
  Every wait on Claude's output is `Wait+Screen@60s /<regex>/`, never a
  fixed `Sleep`, so the tape tolerates model latency.
- `docs/assets/loop.gif` — committed. Budget 3 MB; if the first render is
  over, reduce rows/columns before touching the frame durations.
- `README.md` — the GIF goes directly under the tagline, before "How it
  compares". The existing "Check it worked" text block stays; the image is
  its illustration, not its replacement.
- `docs/getting-started.md` — the storyboard section becomes the four
  frames below and points at the tape.

### Frames

| # | On screen | Wait on | Hold |
|---|-----------|---------|------|
| 1 | `claude` in `app/`; user types `never use npm in this repo, always yarn`; Claude acknowledges. | Claude's reply prompt returning | 3s after reply |
| 2 | `/exit`, then `mnemo learn`. The four output lines; the `learned:` line carries `evidence: "never use npm in this repo, always yarn"`. | `/^learned:/` | 6s |
| 3 | `claude` again; user types `add lodash`; Claude runs `yarn add lodash`, not `npm install`. | `/yarn add lodash/` | 3s |
| 4 | `/exit`, then `mnemo why`; top entry reads `injected  use-yarn-not-npm`. | `/injected\s+use-yarn/` | 5s |

Roughly 30 seconds. Frames 2 and 4 are the proof; they hold longest.

### Acceptance

- `bash tools/demo/setup.sh && vhs tools/demo/loop.tape` produces a GIF
  from a clean `$DEMO_ROOT` twice in a row.
- Frame 2 shows an `evidence:` quote that is verbatim the sentence typed in
  frame 1.
- Frame 4 shows the slug injected, and frame 3 shows Claude choosing yarn.
- If Claude's reply in frame 3 does not use yarn, the recording is discarded,
  not edited: the run gets logged (date, model) in `tools/demo/README.md`
  under "runs", and the tape is retried. The README never carries a
  cherry-picked run without that log.

## Order of work and PRs

1. **PR E — export.** Piece 1 whole, plus the `status` line and the reflex
   skip. Ships alone; useful on its own for Claude users.
2. **PR F — hosts.** Piece 2, on top of E. Closes the MCP + rules half of
   #127; the issue stays open for hooks/transcripts with a comment saying so.
3. **PR G — demo.** Piece 3. Independent of E and F; can run in parallel
   with E by a second writer only because it touches no Python (`tools/demo/`,
   `docs/`, README). Otherwise the one-writer-at-a-time rule from the
   corrections-layer work holds.

Then a `1.3.0` release following `release-pipeline-lessons`: manual
`release.yml` dispatch green on four platforms before the tag.

## Non-goals restated

No hooks or transcript readers for Cursor/Codex. No `.claude/rules` `paths:`
frontmatter (globs) on exported rules. No import from a rules file back into
the vault. No landing page. No change to what the reflex injects or how it
scores.
