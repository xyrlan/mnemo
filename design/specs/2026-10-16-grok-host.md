# Grok Build as a second agent CLI — 2026-10-16

mnemo and mnemo-desktop drive Claude Code alone. This round lets them drive
xAI's Grok Build CLI (`grok`) as well: its sessions get mnemo's memory, its
children are dispatched, delivered and followed like Claude's, and
mnemo-desktop runs, lists and talks to them. The desktop half has its own spec
in mnemo-desktop (`docs/superpowers/specs/2026-10-16-grok-accounts-design.md`);
this one is the contract between the two and the whole of mnemo's side.

Contracts: `design/contracts/2026-10-16-grok-host-wave1.md` (leaves) and
`design/contracts/2026-10-16-grok-host-wave2.md` (the session runtime, which
consumes wave 1's leader client).

## Decisions

1. **The account is the signal.** mnemo-desktop's accounts tab gains a kind
   per account, `claude` or `grok`. The kind of the selected account decides
   which CLI the app starts in a new pane and which one mnemo spawns children
   on. The app exports `MNEMO_AGENT=<kind>` into every pane and job it starts,
   plus the account's own variable (`CLAUDE_CONFIG_DIR` or `GROK_HOME`).
2. **mnemo resolves the CLI in one place**, `mnemo.core.agent_cli.current_cli`:
   `--agent`, then `MNEMO_AGENT`, then `grok` when `GROK_SESSION_ID` is set
   (every command a Grok session runs has it), else `claude`. An unknown name
   is an error, never a fallback.
3. **A session's CLI is recorded with the session, never re-derived.** A child
   keeps the CLI it was spawned on; switching the account later changes only
   what is started next. `Session.agent` carries it for every reader.
4. **Grok children run in Grok's leader.** `grok agent --leader stdio` is an
   ACP (JSON-RPC, one message per line) client of a per-home daemon that keeps
   a session's turn running after the client leaves. It is the only Grok
   surface that gives mnemo what `claude --bg` gives it: spawn detached, list
   live state, send a later turn, close. mnemo speaks it from one module
   (`core/grok/acp.py`) and exposes it as `mnemo grok …` so mnemo-desktop
   never needs its own ACP client.
5. **Grok's short id is the last eight hex digits** of the session id
   (`core/grok/paths.short_id`). Grok ids are UUIDv7, time-prefixed; the first
   eight digits of two children dispatched together collide.
6. **Memory reaches a Grok session through the channels Grok delivers, and
   each one is measured before it counts.** Grok drops `additionalContext`
   from SessionStart and UserPromptSubmit. The briefing therefore travels in a
   file Grok loads at startup, written ahead of the session; per-prompt
   context (reflex, held notices) travels on the first PreToolUse after the
   prompt. Both reaches are measured on real Grok sessions by a tool that
   ships with the hooks (`tools/measure_grok_reach.py`).
7. **Hooks stay one set of commands.** Grok reads `~/.claude/settings.json`
   hooks by default, so a machine with mnemo installed for Claude already
   fires mnemo's hooks in Grok sessions. The hook modules learn to tell a
   Grok payload from a Claude one; nothing is installed twice. A Grok-only
   machine gets the same commands through Grok's own hook files, and mnemo's
   hooks must still run once per event, never twice.
8. **Claude stays byte-for-byte what it is.** With `MNEMO_AGENT` unset and no
   `GROK_SESSION_ID`, every spawn argv, prompt, ledger line and hook output is
   the one master produces today. Each piece proves that with a test.
9. **mnemo's own model calls follow the CLI.** A Grok-only machine has no
   `claude` binary; `extraction.provider` gains `grok-cli`, and an unset
   provider takes the current CLI's. mnemo's helper `grok -p` runs with
   `GROK_CLAUDE_HOOKS_ENABLED=0` so it never fires mnemo's hooks.

## Facts

Measured 2026-10-16 on grok 1.0.60 (`01a8e1c591c0`), model grok-4.7, on a
**free** xAI account, in an isolated `HOME`, unless a line says it was read
from the source (`github.com/xai-org/grok-build`, Apache-2.0, commit
`2bdd1d6`). The probe scripts are not in the repo; each wave-1 piece that
depends on a fact re-measures it in its own tests or live test.

**Hooks**
- Grok reads hooks from `~/.claude/settings.json` and `settings.local.json`
  (home and project), `$GROK_HOME/hooks/*.json`, project `.grok/hooks`, and
  `config.toml`. Claude hooks come from `HOME/.claude`, **not**
  `CLAUDE_CONFIG_DIR` (`xai-grok-hooks/src/discovery.rs:370-392`). `grok
  inspect` lists them as `user [claude]`. Live: all six events fired.
- Payloads carry camelCase keys plus snake_case aliases: `session_id`, `cwd`,
  `prompt` (UserPromptSubmit), `tool_name`, `tool_input`, `tool_response`,
  `transcript_path`, `hook_event_name` (PascalCase, as Claude). SessionStart
  `source` is `new`; SessionEnd `reason` is `channel_closed` or `shutdown`;
  Stop `reason` is `end_turn` (an extra Stop fires at session end).
- `tool_name` is **Grok's own**: `run_terminal_command` (Bash), `read_file`
  (Read; input key `target_file`), `write` (Write; `file_path`, `content`),
  `search_replace` and `hashline_edit` (Edit; `file_path`, `old_string`,
  `new_string`, `replace_all`), `grep`, `list_dir`
  (`xai-grok-tools/src/types/claude_alias.rs:47-55`). Matchers written with
  Claude names still match. mnemo's `pre_tool_use.py` compares `tool_name ==
  "Bash"` and so does nothing in a Grok session today.
- Claude's `hookSpecificOutput.permissionDecision: "deny"` blocks the call;
  the reason reaches the model as `Hook denied: <reason>`.
- `additionalContext` reaches the model from PreToolUse, PostToolUse,
  PostToolUseFailure and Stop. From **SessionStart and UserPromptSubmit it
  never does**: canaries from both were absent from `chat_history.jsonl`
  while PreToolUse/PostToolUse canaries were present (source: SessionStart is
  `dispatch_non_blocking`, UserPromptSubmit `dispatch_prompt_gate`).
- `~/.claude/CLAUDE.md` is loaded **before** SessionStart hooks run: a file a
  SessionStart hook writes is seen by the next session, not this one (two
  runs). Grok also loads `AGENTS.md`, `CLAUDE.md`, `CLAUDE.local.md`,
  `.claude/CLAUDE.md`, `.grok/rules/*.md`, `.claude/rules/`, and home rules
  in `$GROK_HOME/rules/` and `~/.claude/rules/`; project files need folder
  trust (`--trust`, `~/.grok/trusted_folders.toml`). Read from the bundled
  docs; only `~/.claude/CLAUDE.md` was measured.
- Hook env: `GROK_HOOK_EVENT`, `GROK_SESSION_ID`, `GROK_WORKSPACE_ROOT`. Hook
  timeout defaults to 5 s; SessionEnd hooks to 1.5 s
  (`GROK_SESSION_END_HOOKS_TIMEOUT_MS`). Timeouts fail open.
- `GROK_CLAUDE_HOOKS_ENABLED=0` stops Grok reading Claude hooks: 0 hook
  calls in a `-p` run with it set.
- A Notification hook fires with `notificationType` `permission_prompt` or
  `elicitation_dialog` when a session waits on a person, `idle_prompt` after
  60 s idle. StopFailure carries `error: rate_limit` on a rate limit.

**Sessions on disk**
- `<home>/sessions/<urlencoded cwd>/<session id>/` holds `chat_history.jsonl`
  (what the model saw: records typed `system`, `user` (content blocks;
  `synthetic_reason` on injected ones), `assistant` (`content`, `tool_calls`
  `[{id,name,arguments}]`, `model_id`), `tool_result` (`tool_call_id`,
  `content`), `reasoning`), `updates.jsonl` (the hooks' `transcript_path`),
  `events.jsonl` (`turn_started`, `phase_changed`, `permission_requested`,
  `turn_ended{outcome}`), `summary.json` (no status, no pid), `usage.json`,
  `signals.json`. See `core/grok/paths.py` for the naming rule.
- No file on disk says whether a session is running. Live state comes only
  from the leader's roster.

**Leader and ACP**
- `grok agent --leader stdio` auto-spawns `grok agent leader
  --no-exit-on-disconnect --relay-on-demand` in its own process group when no
  leader is listening, and bridges stdio to it.
- Live: a client started a session, sent a prompt running `sleep 25`, and
  exited after 6 s. A second client 41 s later loaded the session; the model
  reported the command had finished with exit 0. The second client's own
  `session/prompt` got a correct answer (`stopReason: end_turn`).
- Methods that worked: `initialize`, `session/new {cwd, mcpServers}` (returns
  `sessionId`), `session/load {sessionId, cwd, mcpServers}`, `session/prompt
  {sessionId, prompt:[{type:"text",text}]}`, and the extensions with a
  leading underscore: `_x.ai/sessions/list` (roster), `_x.ai/session/close`.
  Without the underscore both are "Method not found".
- Roster entries: `sessionId, title, cwd, isWorktree, modelId,
  reasoningEffort, yolo, activity, lastTurnSummary, resident,
  lastChangeUnixMs, origin`. `activity` is `working | idle | needs_input |
  dormant | completed | dead`. Headless (`-p`) sessions are left out.
- A session left idle when its last client disconnects is unloaded as
  `dormant`, and **no SessionEnd fires** — not then, and not when the leader
  is stopped. `_x.ai/session/close` on it answers `notResident`.
- The leader socket is `<home>/leader.sock` unless `GROK_LEADER_SOCKET` names
  another. A home whose socket path exceeds macOS's 103 bytes cannot run a
  leader ("path must be shorter than SUN_LEN"); `grok leader list/kill` only
  find leaders on the default socket.
- Permission requests go to every connected client, first answer wins, and
  are replayed on attach. Whether `_meta.yoloMode` on `session/new` makes a
  session approve its own tools with no client attached is **unconfirmed**:
  the roster reported `yolo: false` for a session created with it.
- `--sandbox` other than off vetoes leader mode.

**CLI**
- `grok -p <prompt> --output-format json` prints `{text, stopReason,
  sessionId, usage, …}`; `-m`, `--effort`, `--always-approve`,
  `--permission-mode`, `-s <uuid>` (new session id), `-r <id>` (resume),
  `--fork-session`. `--disallowedTools` is a *permission deny rule*; tool
  removal is `--disallowed-tools`. There is no `--settings`; per-run config
  is a separate `GROK_HOME`.
- `GROK_HOME` selects the account; `auth.json` (0600, no keychain) holds the
  login; `grok login [--device-auth]`, `grok logout`. Two homes run side by
  side.
- Quota: only ACP `_x.ai/billing` (not measured; source
  `xai-grok-shell/src/extensions/billing.rs`).
- A free account ran every probe above without a limit being hit. `grok
  models` on it lists one model, `grok-4.7` (the default); there is no
  smaller one to pick for cheap helper calls.

## Out of scope

- Moving a running Claude session to a Grok account or back. A switch across
  kinds leaves running sessions where they are.
- Grok's own subagents and `grok worktree`; mnemo keeps its own worktrees.
- `mnemo land` and contracts: unchanged, they never touch the agent CLI.
- Twins (`--twins`) on Grok: refused with a clear message until measured.
- Any change to the vault format.

## How the round is judged

- Every piece keeps Claude byte-identical (decision 8) with a test.
- A Grok child dispatched from mnemo-desktop with a Grok account selected
  runs to a PR, its parent learns it finished, and `mnemo sessions` shows it,
  measured on the free account end to end after wave 2.
- `tools/measure_grok_reach.py` reports, over real Grok sessions, how often
  the briefing and per-prompt context reached the model. Until it has a
  number, the Grok briefing and reflex are not claimed to work.
